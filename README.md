# fe — фронтенд-инструменты в командной строке

`fe` — это одна команда, под которой собирается растущий набор утилит для фронтенд-разработки.
Каждая утилита решает задачу, на которую иначе уходит полдня ручной работы: достать вёрстку из
макета Pixso, свести состояние доступности целого React-проекта в один файл, который можно
открыть двойным кликом и отправить коллеге.

Никакой настройки проекта, никаких плагинов и конфигов. Собранный `fe` — один файл; вы даёте ему
ссылку или путь и получаете готовый артефакт.

## Установка и запуск

### Сборка из исходников

```bash
pnpm install
pnpm build
```

После сборки инструмент запускается так:

```bash
node cli/dist/main.mjs --help
```

**`dist/main.mjs` — один самодостаточный файл.** Внутри уже лежит всё, что нужно для работы:
внешних зависимостей нет, `node_modules` рядом не требуется. Его можно просто скопировать куда
угодно — на другую машину, в чужой проект, в CI-образ — и запустить:

```bash
cp cli/dist/main.mjs ~/bin/fe.mjs
node ~/bin/fe.mjs --version
```

### Установка пакетом

Когда пакет опубликован, всё то же самое доступно как обычная npm-зависимость
`@smart-tools/frontend-cli` с бинарником `fe`:

```bash
pnpm add -D @smart-tools/frontend-cli
fe --help
```

Дальше в примерах используется короткое имя `fe` — подставьте `node cli/dist/main.mjs`, если
запускаете из собранных исходников.

## Общие опции

| Опция              | Что делает                                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| `-o, --out <path>` | куда записать результат (файл или каталог); **необязателен** — см. ниже; принимают его только команды, у которых он указан в `--help` |
| `--lang ru\|en`    | язык вывода: `ru` или `en` (по умолчанию `ru`)                                                                                        |
| `-h, --help`       | список команд со всеми опциями                                                                                                        |
| `-v, --version`    | версия                                                                                                                                |

Переменные окружения — те же, что печатает `fe --help` внизу справки:

| Переменная                                                                | Что задаёт                                                                                                         |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `PIXSO_REMOTE_MCP_URL` / `PIXSO_LOCAL_MCP_URL` / `PIXSO_REMOTE_MCP_TOKEN` | доступ к Pixso — см. [Настройка доступа](#настройка-доступа)                                                       |
| `FE_KITS_DIR`                                                             | каталог корпусов дизайн-систем вместо `~/.fe/kits`: туда пишет `--parse-ui-kit` и оттуда читает `--project-report` |

### Куда попадают файлы

**`-o` необязателен у всех команд.** Если его не передать, файлы всё равно записываются — в
каталог по умолчанию рядом с местом запуска, и он создаётся сам. В конце любая команда печатает
одно и то же: строку-итог, а под ней **абсолютные пути всех записанных файлов**, по одному в
строке. Ровно то же самое показывает и финальная карточка в терминале.

| Команда                            | Без `-o` пишет в                                              |
| ---------------------------------- | ------------------------------------------------------------- |
| `--psvg` / `--phtml` / `--pprompt` | `./fe-out/pixso/<имя>.svg` / `.html` / `.md`                  |
| `--passets`                        | `./fe-out/pixso/<имя>/` — `card.svg`, `.html`, `.md`, `.json` |
| `--project-report`                 | `./fe-out/report.html`                                        |
| `--parse-ui-kit`                   | `~/.fe/kits/<имя>/` — у этой команды `-o` нет вовсе           |

У `--parse-ui-kit` каталог назначения задаётся не флагом, а переменной `FE_KITS_DIR` (см.
[раздел о нём](#дизайн-система-как-данные---parse-ui-kit)). Флаг, которого у команды нет, она не
принимает молча, а отказывается выполняться:

```bash
$ fe --parse-ui-kit eds -o ./corpus.json
флаг -o не поддерживается командой --parse-ui-kit.
запустите `fe --help`, чтобы увидеть список команд.   # код возврата 2
```

`<имя>` — это имя самого макета, приведённое к безопасному имени файла: **guid узла** (`11:10`
→ `11-10`), а для ссылки на дизайн — её `item-id`. Поэтому ссылка и guid одного и того же кадра
дают один и тот же файл. Правило приведения: всё, кроме латиницы, цифр и `. _ -`, заменяется на
`-` (подряд идущие — одним), ведущие и хвостовые `-` и `.` убираются, длина обрезается до 64
символов.

Пути в итоге — всегда абсолютные, так что их можно скопировать или передать дальше:

```bash
fe --psvg 11:10 | tail -1     # абсолютный путь к записанному файлу
```

Всё, что печатается в stdout, можно перенаправлять и складывать в пайпы; сообщения об ошибках и
прогресс идут в stderr отдельно и говорят по-человечески, что именно не так и как это починить.

## Pixso: макет → код

Четыре команды превращают кадр из Pixso в артефакт, с которым можно работать. Источник —
**ссылка на дизайн** (`https://…?item-id=…`, удалённый маршрут) или **guid узла** (например
`11:10`, локальный маршрут через плагин Pixso на этой же машине).

| Команда                           | Что вы получаете                                                       | Без `-o`                    |
| --------------------------------- | ---------------------------------------------------------------------- | --------------------------- |
| `--get-pixso-svg`, `--psvg`       | SVG-рендер кадра                                                       | `./fe-out/pixso/<имя>.svg`  |
| `--get-pixso-html`, `--phtml`     | самодостаточный HTML-рендер кадра                                      | `./fe-out/pixso/<имя>.html` |
| `--get-pixso-prompt`, `--pprompt` | готовый Markdown-промпт по кадру — можно сразу отдать LLM              | `./fe-out/pixso/<имя>.md`   |
| `--get-pixso-assets`, `--passets` | один скан → сразу всё: `card.svg`, `card.html`, `card.md`, `card.json` | `./fe-out/pixso/<имя>/`     |

Самое ценное здесь — `--pprompt`: это не «дамп макета», а собранная спецификация экрана
(размеры, дерево, точные значения), которую модель может верстать пиксель-в-пиксель. А
`--passets` делает один-единственный запрос к макету и раскладывает из него сразу четыре
представления, так что не нужно ходить за одним и тем же кадром четыре раза.

### Примеры

```bash
# SVG без -o → ./fe-out/pixso/11-10.svg, путь напечатан в конце
fe --psvg 11:10

# HTML в конкретный файл
fe --phtml 'https://pixso.net/app/editor/<file-key>?item-id=1%3A23' -o ./card.html

# промпт для LLM
fe --pprompt 11:10 -o ./card.md

# полный набор артефактов; без -o → ./fe-out/pixso/11-10/
fe --passets 11:10

# …или в свой каталог
fe --passets 'https://pixso.net/app/editor/<file-key>?item-id=1%3A23' -o ./out
```

Так выглядит итог `fe --psvg 11:10`, запущенного в пустом каталоге:

```
готово, записано 1 файл
/home/user/work/fe-out/pixso/11-10.svg
```

### Настройка доступа

Приоритет: **флаг → переменная окружения / `.env` → значение по умолчанию**. Файл `./.env` в
текущем каталоге подхватывается автоматически, если он есть.

| Переменная               | Что задаёт                           | Флаг-переопределение |
| ------------------------ | ------------------------------------ | -------------------- |
| `PIXSO_REMOTE_MCP_TOKEN` | токен для работы по ссылке на дизайн | `--token <token>`    |
| `PIXSO_REMOTE_MCP_URL`   | адрес удалённого MCP                 | `--endpoint <url>`   |
| `PIXSO_LOCAL_MCP_URL`    | адрес локального MCP                 | `--endpoint <url>`   |

**Токен нужен только для ссылки на дизайн.** Работа по guid узла идёт через локальный маршрут и
токена не требует вовсе.

Минимальный `.env` рядом с местом запуска:

```
PIXSO_REMOTE_MCP_TOKEN=<ваш токен>
```

## Анализ проекта: `--project-report`

```bash
fe --preport <путь-или-ссылка> [-o ./report.html]
```

Прогоняете **любой** React-проект — и получаете **один самодостаточный `report.html`**:
интерактивный дашборд, который открывается двойным кликом в браузере, работает офлайн и никуда
не ходит по сети. Его можно приложить к задаче, кинуть в чат или сохранить как срез состояния
проекта на сегодня.

Что делает эту команду удобной:

- **Не нужно ничего собирать и устанавливать.** Проверяемому проекту не требуется ни `pnpm
install`, ни сборка — анализ читает исходники как есть.
- **Не важно, чем проект стилизован.** Понимаются обычный CSS, SCSS/Sass, Less, CSS- и
  SCSS-модули, инлайновые style-объекты и css-in-js (styled-components, emotion).
- **Ссылку тоже можно.** Вместо локального каталога можно дать ссылку на репозиторий
  (`https://…`, `git@…`, `file://…`) — он сам клонируется во временный каталог и удаляется
  после анализа.
- **Отчёт — один файл.** Никаких папок с ассетами рядом; недостающие каталоги под `-o` будут
  созданы. Без `-o` отчёт ляжет в `./fe-out/report.html`.

### Что вы увидите в отчёте

Сводка по проекту (сколько файлов просмотрено, сколько находок, как они распределены по
серьёзности) и разбор каждой находки — файл, строка, фрагмент кода с подсветкой, объяснение
«почему это проблема» и что с этим делать.

**Доступность (a11y)** — основной блок:

- базовые правила доступности JSX (`eslint-plugin-jsx-a11y`);
- контрол без доступного имени — скринридер объявит только роль;
- текст, не набирающий контраст против своего фона;
- фокус, скрытый через `outline: none`, без нарисованной замены;
- роль или ARIA-атрибут, которых нет в спецификации;
- роль без обязательных ARIA-атрибутов и роль, дублирующая ту, что у тега уже есть;
- ARIA-связь, ссылающаяся на несуществующий `id`;
- диалог, который не закрывается по Escape или не удерживает фокус.

**Дубликаты компонентов** — структурно одинаковые компоненты, скопированные внутри проекта.

**Сторонние иконки** — импорты чужих пакетов иконок.

### Пример

```bash
fe --preport ./my-app                       # → ./fe-out/report.html
fe --preport ./my-app -o ./report.html
fe --preport https://github.com/<org>/<repo>.git -o ./out/report.html
fe --lang en --preport ./my-app -o ./report.html
```

В конце команда печатает короткий итог, а под ним — путь к отчёту. Вот вывод первой из
команд выше, запущенной без `-o`:

```
дизайн-система: не найдена среди зависимостей проекта — проверяются только общие правила. Указать явно: --ui-kit eds|none
отчёт готов: находок 6 (ошибок 5, предупреждений 1), просмотрено файлов 2
/home/user/work/fe-out/report.html
```

## Дизайн-система как данные: `--parse-ui-kit`

```bash
fe --pkit <имя> [--source <git-url|local-path>]
```

`--project-report` знает про дизайн-систему **eds** не понаслышке: внутрь `fe` вшит её снимок —
токены, компоненты, иконки, публичные сигнатуры и правила доступности. Именно по нему команда
отличает «свой» компонент от чужого, замечает устаревшее свойство и подсказывает штатный вариант
вместо самописного.

Снимок фиксируется в момент сборки `fe`, а дизайн-система живёт дальше. `--parse-ui-kit`
пересобирает его из исходников кита — **прямо на вашей машине, поверх встроенного**.

### Что делает команда

1. **Берёт исходники.** Без `--source` — официальный репозиторий этой дизайн-системы,
   `https://gitverse.ru/sbertech/ui-kit-eds-ce.git`; он клонируется во временный каталог и
   удаляется после. С `--source` — ваш каталог на диске или другая ссылка
   (`https://…`, `git@…`, `file://…`). Локальный каталог остаётся ровно в том виде, в каком был:
   ни `node_modules`, ни изменённых файлов в нём не появится.
2. **Ставит апстрим-пакет кита** в отдельный временный каталог — нужен `npm` в `PATH`. Без него
   команда не «сделает похуже», а честно откажется: корпус без апстрима был бы беднее
   встроенного снимка.
3. **Извлекает пять артефактов** и записывает их в каталог корпуса.

### Куда попадают файлы

`~/.fe/kits/<имя>/` — для eds это `~/.fe/kits/eds/`. Пять файлов:

| Файл                  | Что внутри                         |
| --------------------- | ---------------------------------- |
| `tokens.json`         | дизайн-токены обеих тем            |
| `components.json`     | компоненты кита и их свойства      |
| `kit-a11y.json`       | правила доступности, снятые с кита |
| `kit-icons.json`      | иконки кита                        |
| `kit-signatures.json` | публичные сигнатуры пакетов        |

Каталог целиком переносится переменной **`FE_KITS_DIR`**: она задаёт корень вместо `~/.fe/kits`,
и туда же после этого смотрит `--project-report`. Флага `-o` у команды нет — и, в отличие от
прежних версий, переданный `-o` больше не игнорируется молча, а останавливает запуск с кодом 2.

```bash
fe --pkit eds                                  # → ~/.fe/kits/eds/
fe --pkit eds --source ../ui-kit-eds-ce        # из локального клона
FE_KITS_DIR=./kits fe --pkit eds               # → ./kits/eds/
```

Вывод — итог и пути записанных файлов, как у всех команд, всегда абсолютные (относительный
`FE_KITS_DIR` отсчитывается от текущего каталога и разворачивается в абсолютный путь):

```
корпус eds 1.13.0 собран, файлов: 5
/home/user/.fe/kits/eds/tokens.json
/home/user/.fe/kits/eds/components.json
/home/user/.fe/kits/eds/kit-a11y.json
/home/user/.fe/kits/eds/kit-icons.json
/home/user/.fe/kits/eds/kit-signatures.json
```

### Как это видно в отчёте

`--project-report` сам заглядывает в каталог корпуса и в первой же строке говорит, **по какому
снимку** он считал. Без пересборки:

```
дизайн-система: eds 1.13.0 (встроенная) — определена по зависимостям проекта
```

После `fe --pkit eds` — версия кита, дата сборки корпуса и коммит исходников:

```
дизайн-система: eds 1.13.0 (обновлена 2026-09-02, a282c10) — определена по зависимостям проекта
```

То же самое попадает внутрь `report.html` (`"adapter":{"name":"eds","version":"1.13.0 (updated
2026-09-02, a282c10)"}`), так что по отчёту всегда видно, на каких данных он построен.

**Ничего не ломается, если корпус испорчен.** Файл не читается, не проходит проверку или
отсутствует — запуск не падает: команда пишет предупреждение (с именем файла и причиной),
возвращается к встроенному снимку и доводит отчёт до конца. Пустого каталога `~/.fe/kits`
это не касается — это обычное состояние свежей машины, и оно молчит.

## Требования

- **Node** — 22.18+ или 24.11+ (на этих версиях проверена сборка).
- **pnpm** — 10.18.1 (зафиксирован в `packageManager`); нужен только для сборки из исходников.
- **git** — если анализируете проект по ссылке на репозиторий и для `--parse-ui-kit`:
  клонирование делает он.
- **npm** — только для `--parse-ui-kit`: им ставится апстрим-пакет дизайн-системы.
