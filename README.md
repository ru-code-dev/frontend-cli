# fe — фронтенд-инструменты в командной строке

`fe` — это одна команда, под которой собирается растущий набор утилит для фронтенд-разработки.
Каждая утилита решает задачу, на которую иначе уходит полдня ручной работы: достать вёрстку из
макета Pixso, свести состояние доступности целого React-проекта в один файл, который можно
открыть двойным кликом и отправить коллеге.

Никакой настройки проекта, никаких плагинов и конфигов. Собранный `fe` — один файл; вы даёте ему
ссылку или путь и получаете готовый артефакт.

## Установка и запуск

### Сборка из исходников

```bash
pnpm install
pnpm build
```

После сборки инструмент запускается так:

```bash
node cli/dist/main.mjs --help
```

**`dist/main.mjs` — один самодостаточный файл.** Внутри уже лежит всё, что нужно для работы:
внешних зависимостей нет, `node_modules` рядом не требуется. Его можно просто скопировать куда
угодно — на другую машину, в чужой проект, в CI-образ — и запустить:

```bash
cp cli/dist/main.mjs ~/bin/fe.mjs
node ~/bin/fe.mjs --version
```

### Установка пакетом

Когда пакет опубликован, всё то же самое доступно как обычная npm-зависимость
`@smart-tools/frontend-cli` с бинарником `fe`:

```bash
pnpm add -D @smart-tools/frontend-cli
fe --help
```

Дальше в примерах используется короткое имя `fe` — подставьте `node cli/dist/main.mjs`, если
запускаете из собранных исходников.

## Общие опции

| Опция              | Что делает                                                      |
| ------------------ | --------------------------------------------------------------- |
| `-o, --out <path>` | куда записать результат (файл или каталог); без него — в stdout |
| `--lang ru\|en`    | язык вывода: `ru` или `en` (по умолчанию `ru`)                  |
| `-h, --help`       | список команд со всеми опциями                                  |
| `-v, --version`    | версия                                                          |

Всё, что печатается в stdout, можно перенаправлять и складывать в пайпы; сообщения об ошибках
идут отдельно и говорят по-человечески, что именно не так и как это починить.

## Pixso: макет → код

Четыре команды превращают кадр из Pixso в артефакт, с которым можно работать. Источник —
**ссылка на дизайн** (`https://…?item-id=…`, удалённый маршрут) или **guid узла** (например
`11:10`, локальный маршрут через плагин Pixso на этой же машине).

| Команда                           | Что вы получаете                                                       |
| --------------------------------- | ---------------------------------------------------------------------- |
| `--get-pixso-svg`, `--psvg`       | SVG-рендер кадра                                                       |
| `--get-pixso-html`, `--phtml`     | самодостаточный HTML-рендер кадра                                      |
| `--get-pixso-prompt`, `--pprompt` | готовый Markdown-промпт по кадру — можно сразу отдать LLM              |
| `--get-pixso-assets`, `--passets` | один скан → сразу всё: `card.svg`, `card.html`, `card.md`, `card.json` |

Самое ценное здесь — `--pprompt`: это не «дамп макета», а собранная спецификация экрана
(размеры, дерево, точные значения), которую модель может верстать пиксель-в-пиксель. А
`--passets` делает один-единственный запрос к макету и раскладывает из него сразу четыре
представления, так что не нужно ходить за одним и тем же кадром четыре раза.

### Примеры

```bash
# SVG в stdout
fe --psvg 11:10

# HTML в файл
fe --phtml 'https://pixso.net/app/editor/<file-key>?item-id=1%3A23' -o ./card.html

# промпт для LLM
fe --pprompt 11:10 -o ./card.md

# полный набор артефактов в каталог (-o обязателен)
fe --passets 'https://pixso.net/app/editor/<file-key>?item-id=1%3A23' -o ./out
```

### Настройка доступа

Приоритет: **флаг → переменная окружения / `.env` → значение по умолчанию**. Файл `./.env` в
текущем каталоге подхватывается автоматически, если он есть.

| Переменная               | Что задаёт                           | Флаг-переопределение |
| ------------------------ | ------------------------------------ | -------------------- |
| `PIXSO_REMOTE_MCP_TOKEN` | токен для работы по ссылке на дизайн | `--token <token>`    |
| `PIXSO_REMOTE_MCP_URL`   | адрес удалённого MCP                 | `--endpoint <url>`   |
| `PIXSO_LOCAL_MCP_URL`    | адрес локального MCP                 | `--endpoint <url>`   |

**Токен нужен только для ссылки на дизайн.** Работа по guid узла идёт через локальный маршрут и
токена не требует вовсе.

Минимальный `.env` рядом с местом запуска:

```
PIXSO_REMOTE_MCP_TOKEN=<ваш токен>
```

## Анализ проекта: `--project-report`

```bash
fe --preport <путь-или-ссылка> -o ./report.html
```

Прогоняете **любой** React-проект — и получаете **один самодостаточный `report.html`**:
интерактивный дашборд, который открывается двойным кликом в браузере, работает офлайн и никуда
не ходит по сети. Его можно приложить к задаче, кинуть в чат или сохранить как срез состояния
проекта на сегодня.

Что делает эту команду удобной:

- **Не нужно ничего собирать и устанавливать.** Проверяемому проекту не требуется ни `pnpm
install`, ни сборка — анализ читает исходники как есть.
- **Не важно, чем проект стилизован.** Понимаются обычный CSS, SCSS/Sass, Less, CSS- и
  SCSS-модули, инлайновые style-объекты и css-in-js (styled-components, emotion).
- **Ссылку тоже можно.** Вместо локального каталога можно дать ссылку на репозиторий
  (`https://…`, `git@…`, `file://…`) — он сам клонируется во временный каталог и удаляется
  после анализа.
- **Отчёт — один файл.** Никаких папок с ассетами рядом; недостающие каталоги под `-o` будут
  созданы.

### Что вы увидите в отчёте

Сводка по проекту (сколько файлов просмотрено, сколько находок, как они распределены по
серьёзности) и разбор каждой находки — файл, строка, фрагмент кода с подсветкой, объяснение
«почему это проблема» и что с этим делать.

**Доступность (a11y)** — основной блок:

- базовые правила доступности JSX (`eslint-plugin-jsx-a11y`);
- контрол без доступного имени — скринридер объявит только роль;
- текст, не набирающий контраст против своего фона;
- фокус, скрытый через `outline: none`, без нарисованной замены;
- роль или ARIA-атрибут, которых нет в спецификации;
- роль без обязательных ARIA-атрибутов и роль, дублирующая ту, что у тега уже есть;
- ARIA-связь, ссылающаяся на несуществующий `id`;
- диалог, который не закрывается по Escape или не удерживает фокус.

**Дубликаты компонентов** — структурно одинаковые компоненты, скопированные внутри проекта.

**Сторонние иконки** — импорты чужих пакетов иконок.

### Пример

```bash
fe --preport ./my-app -o ./report.html
fe --preport https://github.com/<org>/<repo>.git -o ./out/report.html
fe --lang en --preport ./my-app -o ./report.html
```

В конце команда печатает короткий итог, например:

```
отчёт готов → ./report.html: находок 6 (ошибок 5, предупреждений 1), просмотрено файлов 2
```

## Требования

- **Node** — 22.18+ или 24.11+ (на этих версиях проверена сборка).
- **pnpm** — 10.18.1 (зафиксирован в `packageManager`); нужен только для сборки из исходников.
- **git** — только если анализируете проект по ссылке на репозиторий: клонирование делает он.
