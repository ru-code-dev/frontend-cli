# Changelog

## 1.2.0 — 2026-10-28

### Установка

- **`bash install`** — релиз теперь три файла: `fg.mjs`, `install` и `ru-code-install` (установщик
  ru-code из свежей сборки HEAD, дословно). `git clone <релиз> && bash <релиз>/install` ставит
  команду `fguard`, три навыка CLI и — если ru-code установлен и не старше 0.0.34 — плагин pixso.
  Повторный запуск — обновление: строки в rc-файлах не дублируются, токен сохраняется.
  `bash install --uninstall` удаляет всё это, в том числе из `<корень ru-code>/fg/install`,
  когда клона уже нет. Подробно — [manual/setup.md](manual/setup.md).
- Node выбирает код установщика ru-code (`check_node_floor`): сначала node, поставляемый с CLI,
  затем `PATH`; нет node или он старый — тот же отказ, что у ru-code, код 1.
- Строку в rc-файлах, `env.sh` и обёртку пишут функции установщика ru-code
  (`create_wrapper`, `clean_rc`, `add_path`) с путями fguard; режим (строка `PATH` или `env.sh`) —
  тот, что вшит в сборку ru-code. ru-code и fguard не трогают строки друг друга.

### Команды

- **Команда называется `fguard`**: `fg` — встроенная команда bash и zsh. Справка, примеры,
  сообщения и `bin` в `cli/package.json` — `fguard`. Имена файлов (`fg.mjs`, `fg-out/`,
  `fg.config.json`) не менялись.
- **`fguard token [<токен>]`** — пишет `PIXSO_REMOTE_MCP_TOKEN` в `.env` рядом с `fg.mjs`
  (права 600) и печатает путь; без значения — скрытый ввод. Этот файл читается после окружения и
  `./.env`. Подробно — [manual/token.md](manual/token.md).
- Команды Pixso: нет токена или сервер его отклонил (HTTP 401/403) — **код 3** и строка с
  `fguard token <ваш токен>` и путём к файлу (раньше: код 2 и три способа).
- **`--preport --format summary`** — `report.summary.json`: здоровье, итоги, доли компонентов,
  покрытие токенами, топ-5 проблем и абсолютные пути файлов запуска; цифры считает код самого
  дашборда. Работает в списке (`html,summary`).

### Навыки CLI

- `fg:get-pixso-specs`, `fg:get-pixso-html`, `fg:project-report` в `<папка CLI>/skills/`, по-русски,
  с абсолютными путями node и `fg.mjs`. Подробно — [manual/skills.md](manual/skills.md).

### Прочее

- `engines`: `node >=22.16` (все проверки пройдены на официальном v22.16.0 и на текущем node).
- `vendor/ru-code/` обновлён из свежей сборки HEAD и теперь содержит `install`.

## 1.1.0 — 2026-10-26

### Команды

- **`fguard install`** — ставит плагин pixso в ru-code. Сборка плагина вшита в `fg.mjs`. Корень
  ru-code fguard берёт у собственного preflight-скрипта ru-code (тоже вшит) и пишет только в
  `<корень ru-code>/plugins/pixso`. Замена атомарная: новая папка сверяется по sha256 и только
  потом встаёт на место старой; при сбое старая возвращается. Данные плагина и переключатели
  вкл/выкл не трогаются. Если файлы не изменились, ничего не пишется.
- **`fguard install --check`** — только проверка: где ru-code, установлен ли плагин и совпадает ли
  со встроенным, не перекрыт ли копией самого ru-code, запущен ли ru-code. Код `0` — всё в
  порядке, иначе `1`.
- **`fguard uninstall`** — удаляет `<корень ru-code>/plugins/pixso`; данные плагина остаются.
- Перезапуск: `ru-code restart --no-browser`, только если ru-code запущен и файлы изменились;
  `--no-restart` его отключает. Запуск — как у установщика ru-code: node напрямую
  (`<node> <флаги> <корень>/bin/cli.js restart --no-browser`), без sh-обёртки, одинаково на всех ОС;
  node — тот, что установщик записал в `bin/ru-code`, иначе `node` из PATH. Окружение — то, с
  которым запущен fguard, без `.env` проекта и настроек Pixso. Неудачный перезапуск — предупреждение и
  код `1`, плагин остаётся установленным.
- Служебные папки fguard — только `<корень ru-code>/.fg-install/` (`lock`, `new`, `old`), вне
  `plugins/`: ru-code считает плагином любую папку в `plugins/`. Блокировка не даёт двум запускам
  пересечься; после сбоя следующий запуск возвращает старую копию плагина.
- Если текущая версия ru-code сама поставляет pixso — громкое предупреждение: ru-code загрузит
  свою копию.
- Минимальная версия ru-code — `MINIMUM_APP_VERSION = "0.0.34"`
  (`packages/fg-install/src/constants.ts`): встроенной сборке pixso нужен API хоста, которого нет
  в 0.0.33. Версия берётся из `<корень ru-code>/bin/current.json` и сравнивается как в ru-code
  (`X.Y.Z`, суффикс `-rc…` не учитывается). Старее или не прочитать — `fguard install` выходит с кодом
  `1`, ничего не записав (`✖ установлен ru-code 0.0.33, а плагину pixso нужен 0.0.34 или новее`);
  `--check` показывает обе версии и тоже выходит с `1`; `fguard uninstall` версию не проверяет.
- Команды-слова: первым словом идёт команда (`fguard install`), справка — `fguard --help install`.

### Сборка

- Каталог `vendor/ru-code/` (preflight + одна папка плагина) вшивается в бандл со сжатием brotli
  и sha256 каждого файла; без него сборка падает. Сборка падает и тогда, когда во вшиваемых
  файлах найдена запрещённая строка (общий список с проверкой репозитория —
  `packages/fg-install/src/forbidden.ts`). Бандл вырос примерно на 0,6 МБ.

## 1.0.0 — 2026-09-13

Первый релиз **Frontend Guard** (`fguard`).

### Дистрибутив

- Один самодостаточный файл `fg.mjs` без внешних зависимостей; у публикуемого манифеста
  `cli/package.json` нет ключа `dependencies`, bin — `fguard`.
- `pnpm release` собирает всё и кладёт бандл в корень репозитория как `fg.mjs`, проверяя размер
  по коридору 18–25 MiB.

### Команды

- **Pixso:** `--psvg` / `--get-pixso-svg`, `--phtml` / `--get-pixso-html`, `--pprompt` /
  `--get-pixso-prompt`, `--passets` / `--get-pixso-assets`. Маршрут выбирается по аргументу:
  ссылка `http(s)://…` — удалённый (нужен токен), guid узла — локальный. `--passets` делает один
  запрос к макету и пишет `card.svg`, `card.html`, `card.md`, `card.json`.
- **`--preport` / `--project-report`** — отчёт по проекту: каталог на диске либо ссылка на
  репозиторий (`http(s)://…`, `git@…`, `file://…`) с клонированием во временный каталог и
  уборкой следом.
- **`--iconf` / `--init-config`** — `fg.config.json` и `fg.config.schema.json`; существующий файл
  никогда не перезаписывается.
- **`--pkit` / `--parse-ui-kit`** — пересборка корпуса дизайн-системы из её исходников,
  `[--source <путь|repo>]`.

### Общие опции

`-o, --out` (необязателен у каждой команды), `--lang ru|en` (по умолчанию `ru`), `--verbose`,
`--token`, `--endpoint`, `-h, --help` (и страница команды: `fguard --help --preport`),
`-v, --version`. Необъявленный флаг, флаг не для этой команды, две команды за раз и неизвестный
язык — выход с кодом 2 и локализованным сообщением.

### Форматы и коды возврата

- `--format html|compact|json|sarif`, несколько через запятую; проект читается один раз.
  `html` — самодостаточный отчёт, `compact` — консольный документ, `json` — форма `eslint -f json`,
  `sarif` — SARIF 2.1.0. `-o` называет файл для одного формата-файла и каталог для нескольких.
- Коды возврата: `0` — видимых ошибок нет, `1` — есть видимая ошибка либо запуск сорвался,
  `2` — неверный вызов.

### Конфигурация правил

- `fg.config.json` (`analyzer.{uiKit, ignore, default, categories, rules}`), схема
  `fg.config.schema.json` с локализованными описаниями и встроенным уровнем каждого правила в
  подсказке редактора.
- Уровни `off | on | error | warning | info | candidate` и файловый `inherit`, который загрузчик
  выбрасывает до анализа. Восемь категорий: `token`, `typography`, `font`, `api`, `override`,
  `component`, `icon`, `a11y`.
- Приоритет уровня: `<правило>/<подвид>` → самый длинный подходящий ключ `rules` → категория →
  `default`. Поиск файла: `--config` → корень проекта → текущий каталог → умолчания.
- Правила всегда выполняются; конфигурация ложится слоем поверх результата, поэтому в отчёт
  попадают все находки, а в дашборде их можно вернуть.

### Анализатор

- 11 общих правил: доступность JSX (`eslint-plugin-jsx-a11y`), отсутствующее доступное имя,
  контраст текста, подавленный фокус, несуществующие роли и ARIA-атрибуты, обязательные и
  избыточные ARIA, ARIA-связи с несуществующим `id`, фокус в диалоге, дубликаты компонентов,
  сторонние пакеты иконок.
- Стили: обычный CSS, SCSS/Sass, Less, CSS- и SCSS-модули, инлайновые style-объекты,
  styled-components, emotion, JSS, шаблонные литералы, vanilla-extract.

### Дизайн-системы

- Адаптер EDS с двумя профилями — **eds** (1.x) и **eds2** (2.x); всё, что зависит от версии,
  вынесено в `KitProfile`, правила общие. Автоопределение по зависимостям проекта,
  `--ui-kit eds|eds2|none` для явного выбора.
- Снимок каждой вшит в бандл: токены, компоненты, иконки, публичные сигнатуры, правила
  доступности. С дизайн-системой — 32 правила против 11 общих.
- Корпус на диске (`~/.fg/kits/<кит>/`, переносится `FG_KITS_DIR`) перекрывает встроенный
  снимок; не прошедший проверку файл даёт предупреждение и откат к встроенному, а не сбой.
- `fg-kit-extract` — отдельный bin: компоненты и типы React-пакета дизайн-системы через
  ts-morph, вывод детерминированный.

### Дашборд

- Самодостаточный `report.html`: пять экранов (Сводка, План работ, По файлам, Дизайн-система,
  Доступность), клавиши `1`–`5`, `/` — поиск, `Esc` — сброс фильтров.
- Метрики здоровья и внедрения, группировка находок в решения по эффекту, пометка авто-фиксов,
  панель «Правила» с живым пересчётом поверх встроенной конфигурации.

### Терминал

- Единая грамматика для всех команд: заголовок `fg v<версия> · <команда> · …`, живая строка в
  терминале либо строка на фазу в пайпе, итоговый блок с абсолютными путями.
- `stdout` — только данные (документ `compact` или пути записанных файлов, и только когда это не
  терминал); всё для человека — в `stderr`.
- `NO_COLOR`, `FORCE_COLOR`, `COLORTERM` учитываются; `NO_COLOR` выключает цвет, а не режим вывода.
- `./.env` читается автоматически; приоритет — флаг > окружение / `.env` > умолчание.
- Все пользовательские строки локализованы (`ru`, `en`).

### Документация и проверки

- Проверки: `pnpm build`, `pnpm typecheck`, `pnpm test`, `pnpm lint`; по требованию
  `pnpm test:integration` и `pnpm test:e2e`.
- Прогон `pnpm test:e2e` (Playwright) обходит матрицу из 43 состояний консоли и пишет
  `docs/screenshots/` — снимок на состояние плюс `gallery.html` и два снимка дашборда.
