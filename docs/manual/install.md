# `install` / `uninstall` — плагин pixso в ru-code

```
fg install [--check] [--no-restart]
fg uninstall [--no-restart]
```

`fg install` кладёт встроенную в `fg.mjs` сборку плагина pixso в ru-code. `fg install --check`
только проверяет и ничего не меняет. `fg uninstall` удаляет плагин.

Это команды-слова, без дефисов: первым словом идёт команда, за ней — флаги. Справка по команде:
`fg --help install` (так же работают `fg install --help` и `fg --help --install`).

## Где ru-code

fg не угадывает, где лежит ru-code. Он запускает **собственный preflight-скрипт ru-code** — тот
же, которым пользуется установщик ru-code, — и берёт корень приложения из строки `OUR_ROOT=` его
вывода. Скрипт вшит в `fg.mjs`; перед запуском он записывается во временный каталог, а после
запуска удаляется. Поэтому fg и установщик ru-code всегда сходятся в том, где ru-code: в
`~/.ru-code`, а на Linux — в `/home/work/<пользователь>/.ru-code`, если существует каталог
`/home/work/<пользователь>` (сам `.ru-code` внутри него может ещё не быть).

Переменные `T3CODE_HOME` и `RU_CODE_PLUGINS_DIR` и флаг ru-code `--base-dir` служат ru-code для
разработки и тестов, fg их **не читает**.

Проверки preflight (node, CLI-движок, git) выводятся строкой `проверки`. Если какая-то из них не
пройдена, установка всё равно продолжается: плагину эти проверки не нужны.

## Что трогает `fg install`

| Путь                                              | Что происходит                                                                                          |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `<корень ru-code>/plugins/pixso`                  | заменяется целиком — **единственное** место в ru-code, куда пишутся файлы плагина                       |
| `<корень ru-code>/.fg-install/`                   | рабочий каталог самого fg: блокировка, сборка новой папки, копия старой на время замены. Вне `plugins/` |
| `<корень ru-code>/userdata/plugins/pixso`         | данные плагина — не трогаются                                                                           |
| `<корень ru-code>/userdata/plugins/disabled.json` | переключатели вкл/выкл — не трогаются                                                                   |
| `<корень ru-code>/bin`                            | только читается: `cli.js`, `current.json` (версия ru-code)                                              |

Порядок такой:

1. **ru-code должен быть установлен** — то есть должен существовать `<корень>/bin/cli.js`.
   Если файла нет, команда выходит с кодом 1 и ничего не пишет.
2. **Встроенный плагин проверяется** по правилам загрузчика ru-code: `id` подходит под шаблон и
   совпадает с именем папки, `apiVersion` равен 2, файлы `server`/`web`/`styles` лежат внутри
   плагина. Если ru-code такой плагин пропустил бы, fg его не ставит (код 1).
3. **Версия ru-code должна быть не старше минимальной** — см. [ниже](#минимальная-версия-ru-code).
   Если она старше или её не прочитать, команда выходит с кодом 1 и ничего не пишет.
4. **Проверяется, нет ли собственной копии у ru-code.** Если текущая версия ru-code
   (`bin/current.json`) сама поставляет `plugins/pixso`, ru-code загрузит свою копию, а
   установленную fg проигнорирует. fg предупреждает об этом (`!`), но ставит плагин всё равно.
5. **Замена атомарная.** Новая папка собирается в `<корень>/.fg-install/new/` и сверяется по
   sha256 с тем, что вшито. Только после этого старая папка переименовывается в
   `.fg-install/old/`, новая встаёт на её место, а `old/` удаляется. Если на этом шаге что-то
   сорвалось, старая папка возвращается на место; при этом fg показывает исходную ошибку, а ошибку
   отката прикладывает к ней как причину. Если плагины ru-code лежат на другом диске, чем корень
   (переименование между дисками невозможно), замена выходит с ошибкой, и установленная папка
   остаётся нетронутой.

   Рабочий каталог лежит **вне** `plugins/` намеренно: ru-code читает каждую вложенную папку
   `plugins/`, и скрытые тоже (`apps/server/src/ru-code/plugins/scan.ts:62-88`), так что любая
   временная папка там появилась бы в настройках как сломанный плагин. Имена в `.fg-install/`
   постоянные: `lock/`, `lock.takeover/`, `new/`, `old/`.
   - **Блокировка.** `.fg-install/lock/` создаётся атомарно (`mkdir`), внутри файл `pid`. Если
     другой `fg install`/`fg uninstall` уже работает, команда выходит с кодом 1 и ничего не
     меняет. Блокировка мёртвого процесса считается устаревшей и перехватывается; перехват
     сам защищён второй атомарной папкой `.fg-install/lock.takeover/`, поэтому из двух запусков,
     одновременно нашедших устаревшую блокировку, её получает только один, второй выходит с кодом 1.
   - **После сбоя в середине замены** (процесс убит между двумя переименованиями) прежний плагин
     лежит только в `old/`: при следующем запуске fg сначала возвращает его на место, и только
     потом чистит `new/` и `old/`.

6. **Перезапуск** — см. ниже.

Если та же сборка уже установлена (все файлы совпадают байт в байт), ничего не пишется и
ничего не перезапускается: `✔ плагин pixso 1.0.0 уже установлен`.

Флага `-o` у этих команд нет: в текущий каталог они ничего не пишут. `fg install -o x` выходит с
кодом 2.

```
$ fg install
fg v1.1.0 · install
  поиск ru-code          /home/user/.ru-code  0.0s
  проверка плагина       pixso 1.0.0  0.0s
  запись                 0.0s
  перезапуск ru-code     0.0s
✔ плагин pixso 1.0.0 установлен                    0.0s
  плагин      /home/user/.ru-code/plugins/pixso
  данные      /home/user/.ru-code/userdata/plugins/pixso
  проверки    node ok · cli fail (missing) · git ok
  перезапуск  выполнен: ru-code restart --no-browser
```

Если `stdout` не терминал (пайп, CI) и файлы были записаны, в него печатается путь установленной
папки — одна строка. Если плагин уже установлен без изменений, а также при `uninstall`, в `stdout`
ничего не печатается.

## Минимальная версия ru-code

Встроенная сборка pixso вызывает API хоста (`ctx.publish`), которого нет в ru-code 0.0.33: там
ru-code пометил бы плагин как сломанный, хотя установка прошла бы успешно. Поэтому у fg есть
константа `MINIMUM_APP_VERSION = "0.0.34"` (`packages/fg-install/src/constants.ts`) — первый
выпуск ru-code после коммита с этим API (в самом ru-code номер версии пока 0.0.33).

- **Откуда берётся версия.** Из поля `version` файла `<корень ru-code>/bin/current.json` — по
  этому файлу лаунчер ru-code решает, какую версию запускать (`{ "schema": 1, "version":
"0.0.34", "entry": "versions/0.0.34/cli.js" }`).
- **Как сравнивается.** Как у самого ru-code: числа `X.Y.Z` по очереди — мажор, минор, патч.
  Префикс `v` допускается; всё после патча (`-rc.1`, `+сборка`) не учитывается, так что
  `0.0.34-rc.1` считается 0.0.34.
- **Старее минимальной** — код 1, ничего не записано, прежняя папка плагина (если была) не тронута:

  ```
  ✖ установлен ru-code 0.0.33, а плагину pixso нужен 0.0.34 или новее
    обновите ru-code и повторите fg install
    подробнее:      fg install … --debug
  ```

- **Версию не прочитать** (нет `current.json`, он не разбирается, в `version` нет `X.Y.Z`) — тоже
  код 1 и ничего не записано, со своим сообщением:
  `✖ не удалось узнать версию ru-code, а плагину pixso нужен 0.0.34 или новее`.
- **`fg install --check`** показывает строки `версия ru-code` и `нужен ≥ 0.0.34`; если ru-code
  старее или версию не прочитать — код 1 с той же причиной в заголовке.
- **`fg uninstall`** версию не проверяет: удалить плагин можно всегда.

**Когда поднимать.** Когда новая сборка плагина в `vendor/ru-code/plugins/` требует более нового
ru-code — поменяйте строку в `constants.ts` (и ожидания в тестах, которые её называют).

## Перезапуск

ru-code читает плагины только при старте, поэтому новый плагин начинает работать после
перезапуска.

- **ru-code запущен** (в `<корень>/userdata/server-runtime.json` записан pid живого процесса) —
  fg запускает `ru-code restart --no-browser` так же, как это делает установщик ru-code: сам
  node, без sh-скрипта: `<node> --experimental-sqlite --disable-warning=ExperimentalWarning
<корень>/bin/cli.js restart --no-browser`. Так на любой ОС, одним путём; запуск скрипта из
  `bin` на некоторых машинах запрещён, а `node cli.js` работает. `<node>` — тот, что установщик
  записал в `bin/ru-code` (если файл node ещё есть), иначе `node` из PATH; node, на котором
  работает сам fg, не подставляется: сервер ru-code должен подняться на node установщика.
  `--no-browser` нужен, чтобы перезапуск не открывал новую вкладку браузера.
  Окружение перезапуска (и preflight) — то, с которым запущен fg в оболочке: переменные из
  `./.env`, настройки `PIXSO_*` и `--token` в него не попадают.
- **ru-code не запущен** — fg его не запускает: `· ru-code не запущен — плагин загрузится при
следующем запуске`.
- **`--no-restart`** — перезапуска нет, даже если ru-code запущен. Применить изменения можно
  потом, командой `ru-code restart`.
- **Файлы не изменились** — перезапуска нет.
- **Перезапуск не удался** — плагин остаётся установленным, fg предупреждает (`!`) и выходит с
  кодом 1.

## `fg install --check`

Только читает: ничего не пишет, ничего не перезапускает.

```
$ fg install --check
fg v1.1.0 · install --check
  поиск ru-code          /home/user/.ru-code  0.0s
  проверка плагина       pixso 1.0.0  0.0s
✔ плагин pixso 1.0.0 установлен и совпадает со встроенным  0.0s
  ru-code         /home/user/.ru-code
  версия ru-code  0.0.34
  нужен           ≥ 0.0.34
  проверки        node ok · cli fail (missing) · git ok
  плагин          /home/user/.ru-code/plugins/pixso
  установлен      да, совпадает со встроенным
  встроенный      pixso 1.0.0
  перекрыт        нет
  запущен         нет
  перезапуск      не понадобится
```

Код возврата `0` — ru-code установлен и не старше минимальной версии, плагин установлен, совпадает со встроенным и не перекрыт
копией ru-code. Во всех остальных случаях — `1`: плагина нет, установлен другой, ru-code
поставляет свою копию, ru-code старее минимальной версии, не удалось прочитать `bin/current.json`
или ru-code не установлен.
Строка `перезапуск` говорит, понадобится ли перезапуск при `fg install`.

## `fg uninstall`

Удаляет `<корень ru-code>/plugins/pixso` — и только эту папку. Данные плагина
(`userdata/plugins/pixso`) и переключатели остаются: если поставить плагин снова, он их увидит.
Перезапуск — по тем же правилам, что у `install`, включая `--no-restart`. Если плагина нет —
`✔ плагин pixso не был установлен — удалять нечего`, код 0. Для удаления ru-code не обязан быть
установлен: команда уберёт оставшуюся папку плагина.

## Коды возврата

| Код | Когда                                                                                                                                                                                                                      |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0` | установлено (или уже было), удалено (или нечего удалять); `--check`: всё в порядке                                                                                                                                         |
| `1` | ru-code не установлен или старее `MINIMUM_APP_VERSION` (или его версию не прочитать), preflight не сообщил корень, плагин не прошёл бы проверку ru-code, запись не удалась, перезапуск не удался; `--check`: что-то не так |
| `2` | неверный вызов: лишний аргумент, флаг не для этой команды (`-o`, `--check` у `uninstall`)                                                                                                                                  |

## Прерывание

`Ctrl+C` (а также SIGTERM и SIGHUP) во время поиска ru-code останавливает preflight вместе с
его дочерними процессами и удаляет его временный каталог; fg завершается тем же сигналом. На
Windows группы процессов нет: останавливается только сам preflight.

## Windows

Перезапуск на Windows устроен так же, как на остальных ОС (см. «Перезапуск»): `<node>` берётся из
`bin/ru-code`, который установщик пишет и на Windows. На Windows этот путь не проверялся запуском.
